## 3. จุดที่พัง เรียงตามความเสี่ยง

### P0 — ความปลอดภัย/ข้อมูลส่วนบุคคล (ควรจัดการก่อน)

**F1. Token ของ LINE OA และเพจ Facebook เก็บเป็นข้อความธรรมดาในชีต**
แท็บ `CONFIG` มี `LINE_Channel_Access_Token` และ `FB_Pages` (JSON ที่มี page access token ของทุกเพจ) แบบอ่านได้ตรง ๆ ใครเปิดชีตนี้ได้ = ส่งข้อความในนาม OA และจัดการเพจได้ทั้งหมด และชีตนี้ถูกขอสิทธิ์/แชร์กันในแชต (15 ก.ค.)
ผลถ้าหลุด: ยิงข้อความหาลูกค้าในนามคลินิก, ลบ/แก้โพสต์, ดึง insight ทั้งหมด

**F2. รหัสผ่านบัญชีแพลตฟอร์มส่งในแชตกลุ่ม**
31 ก.ค. มีการพิมพ์อีเมล + รหัสผ่าน + เบอร์ที่ใช้สมัคร RedNote ลงในกลุ่ม LINE (ค้างอยู่ในประวัติแชตถาวร และอยู่ในไฟล์ export ที่หน้าเดสก์ท็อป)

**F3. ข้อมูลบัตรประชาชนอยู่ในชีตการตลาด**
มีแท็บที่มีคอลัมน์ `เลขบัตร ปชช.` + `รูปบัตร (Drive)` + `เบอร์โทร` + `LINE User ID` อยู่ในไฟล์เดียวกับแผนคอนเทนต์ = ทีมคอนเทนต์/ฝึกงานที่เปิดชีตได้ เห็นบัตรประชาชนลูกค้าได้ทั้งหมด (PDPA)

### P1 — Flow พัง ทำให้งานหายและวัดผลไม่ได้

**F4. สองแหล่งความจริงที่ไม่ผูกกัน**
คอลัมน์ `Trello URL` ในชีตไม่มีการกรอก และการ์ด Trello ไม่มีเลขอ้างอิงชีต → ชิ้นงานเดียวกันถูกนับสองที่ ไม่มีใครรู้ว่าตรงกันหรือไม่ (ชีต 492 vs Trello 1,309)

**F5. ชีตหยุดสะท้อนความจริงตั้งแต่กรกฎาคม**
ชีตมีงาน ก.ค. = 2 ชิ้น, ส.ค. = 9 ชิ้น แต่ 15 ก.ค. ตองรายงานผลงานเดือน ส.ค. "ลำดับ 453–537" (~85 ชิ้น) และ Trello สร้าง 115 การ์ดในเดือน ก.ค.
→ Morning Brief / KPI / รายงานผู้บริหาร อ่านจากชีตนี้ = อ่านข้อมูลที่ตายแล้ว

**F6. ลิสต์ "ผ่านการรีวิว" เป็นหลุมดำ**
227 ใบ นิ่งเฉลี่ย 99 วัน — งานผ่านรีวิวแล้วไม่มีขั้นตอนบังคับให้ไปต่อ (ไม่มีวันโพสต์ ไม่มีเจ้าของ) ใบที่ค้างนานสุดในลิสต์ "แก้ไข" คือ 332 วัน (`sport_massage`, `โปรก้าวแรก 790`, `เคสโฮม`, `คลิปโปร KNEE PRP THERAPY`)

**F7. บอร์ด 29 ลิสต์ ปนกัน 3 แกน**
มีทั้งลิสต์ตามสเตจ (วางแผน/แก้ไข/ผ่านการรีวิว), ตามเดือน (กรกฎาคม 2569, โปรเดือนสิงหาคม), ตามประเภท (Ads, HomeProgram, ไอเดีย) และลิสต์สรุปย้อนหลัง 6 ลิสต์ → การ์ดใบหนึ่งควรอยู่ลิสต์ไหนไม่มีคำตอบเดียว นี่คือสาเหตุรากของ F6

**F8. คำสถานะไม่ถูกคุม**
CONFIG กำหนด 8 สถานะ แต่ข้อมูลจริงมี 13 แบบ รวมของซ้ำที่สะกดต่างกัน `รอตั้งโพส` (28) กับ `รอตั้งโพสต์` (28), ว่าง 17, และมีแถว `[ทดสอบ]` ปนอยู่ในข้อมูลจริง
→ ตรงกับอาการที่บอทแจ้ง 10 มิ.ย.: 15:28 "ก.ค. 0% ค้าง 56 ชิ้น" แล้ว 18:00 วันเดียวกัน "75% ค้าง 18 ชิ้น"

**F9. ชื่อคนไม่ถูกคุม**
`แป้ง` vs `เเป้ง` (สะกดด้วย เ เ ซ้อน 17 ชิ้น), `ปาย` vs `ปายฝน`; CONFIG ระบุทีม = ตอง, ปาย, แป้ง, แฟร์ แต่ข้อมูลจริงมี แยม 53 ชิ้น และ ครีม 42 ชิ้น → KPI รายคนนับไม่ครบทุกกรณี

**F10. วันที่พังหลายชั้น**
- ช่อง "เดือน" ที่ควร auto-fill จาก Publish Date ว่าง 227 จาก 492 (46%)
- มีเดือนขยะ `1970-01` (4 ชิ้น) และ `0626-08` (พิมพ์ปี พ.ศ. เข้าไป)
- ฟอร์แมตวันปนกันในตารางเดียว (`2026-03-17` กับ `15/5/2026`)
- เวลาเช็คอินถูกเก็บเป็น `Sat Dec 30 1899 08:53:43` (บั๊ก date-serial ของ Sheets) → คำนวณ "มาสาย/ตรงเวลา" จากค่านี้ไม่ได้จริง

**F11. ลูปวัดผลขาดตอน**
`engagement` = 0 ทุกชิ้น, แท็บ PLATFORM_ANALYTICS ว่าง, `content_kpi` 0 แถว — แต่สูตร KPI ให้น้ำหนัก Platform 15% + Quality 15%
→ คะแนนที่คำนวณได้จริงเหลือแต่ Discipline (การกรอกฟอร์ม) ซึ่งทุกคนได้เกือบเต็มทุกวัน

**F12. ตัวชี้วัดขัดกับความจริง**
EOD เฉลี่ย 92–100% ทุกเดือน สวนทางกับงานค้าง 227 + 63 ใบ → ระบบกำลังวัด "การกรอกฟอร์มตอน 18:00" ไม่ได้วัด "งานเดินถึงโพสต์"

**F13. โปรโมชั่นไม่มีผลลัพธ์กลับ**
PROMO_MONTHLY เดือน ก.ค. 12 รายการ ตั้งเป้าเคส + Est. Revenue รวม ~1.28 ลบ. แต่คอลัมน์ "เคสจริง" ว่างทั้งหมด และคอนเทนต์ผูกโปรแค่ 3.7% → เลือกโปรเดือนถัดไปด้วยความรู้สึก ไม่ใช่ผลจริง

**F14. งานอัตโนมัติที่ตั้งไว้ ไม่ได้ยิงจริง**
EMAIL_LOG มีแค่ 8 แถว (ล่าสุด 10 มิ.ย.) ทั้งที่ CONFIG ตั้งเตือน deadline รายวัน 08:00 + weekly + รายงานวันที่ 10/15/25/28 และช่องอีเมลผู้รับของทีมคอนเทนต์ / Ad Ops / CEO / Weekly **ว่างเปล่า** → ระบบเตือนตายเงียบโดยไม่มีใครรู้

**F15. CONFIG ค้างเดือน**
`Current_Month = 2026-06` ขณะที่วันนี้ 11 ส.ค. → ทุกสูตร/บอทที่อิงเดือนปัจจุบันคิดจากเดือนที่ผิดมา 2 เดือน

### P2 — ปัญหารอง แต่ทำให้เสียเวลาซ้ำ ๆ

**F16.** ท่อ `sheet_ingest` เข้า hub เก็บได้แค่ ~11 คอลัมน์แรกของ MONTHLY_PLANNER และ 1 คอลัมน์ของแท็บอื่น → สำเนาในฐานข้อมูลไม่ครบ ใช้ตรวจย้อนหลังแทนชีตไม่ได้

**F18.** สิทธิ์เข้าถึงสับสน — 15 ก.ค. เจ้าของธุรกิจขอสิทธิ์เปิดชีตเองไม่ได้ ต้อง request 2 รอบ (ปนกันระหว่าง `marketing@`, `thanchanok.k@`, gmail ส่วนตัว)

## 4. ข้อเสนอ

### A. ทำได้ทันที (ไม่ต้องเขียนโค้ด, ~1–2 ชม.)
1. **ถอด token ออกจากชีต** ย้ายไป Script Properties / Supabase secrets แล้ว **revoke + ออกใหม่** ทั้ง LINE channel token และ page token (ต้องขออนุมัติก่อนทำ เพราะระบบที่ใช้ token เดิมจะดับชั่วคราว)
2. **ย้ายแท็บที่มีเลขบัตรประชาชน** ออกไปเป็นไฟล์แยก จำกัดสิทธิ์เฉพาะคนที่ต้องใช้
3. **เปลี่ยนรหัสผ่าน RedNote** ที่ส่งในแชต และตั้งกติกา "ไม่ส่งรหัสผ่านในกลุ่ม" (ใช้ที่เก็บรหัสกลางแทน)
4. อัปเดต `Current_Month` เป็น 2026-08 + เติมอีเมลผู้รับที่ว่างทั้ง 4 ช่อง
5. ล้างสถานะซ้ำ (`รอตั้งโพส`/`รอตั้งโพสต์`) + ลบแถว `[ทดสอบ]` + แก้ชื่อ `เเป้ง` → `แป้ง` + ตั้ง data validation ให้บังคับ dropdown

### B. จัดโครง flow ใหม่ (2–4 สัปดาห์)
6. **เลือกแหล่งความจริงเดียว** — เสนอ: **Trello = ที่ทำงาน**, **hub = ที่วัดผล**, ชีตเลิกเป็นต้นทาง (เหลือไว้ดูอย่างเดียว) เพราะทีมใช้ Trello จริงอยู่แล้วและ `trello_ingest` ดึงเข้า hub รายวันได้แล้ว
7. **ยุบ 29 ลิสต์ → 7 สเตจ** (ไอเดีย → วางแผน → ผลิต → ตรวจ → แก้ไข → รอโพสต์(มีวันที่) → โพสต์แล้ว) แล้วใช้ label แทนเดือน/ประเภท
8. **กติกาการ์ด**: ทุกใบต้องมี เจ้าของ + กำหนดส่ง; ลิสต์ "รอโพสต์" ต้องมีวันโพสต์เสมอ; ตั้ง WIP limit ที่ลิสต์ "แก้ไข"
9. **นิยาม "เสร็จ"** = มีลิงก์โพสต์จริง + thumbnail + promo_id → ถ้าไม่ครบ การ์ดกลับไปลิสต์เดิม
10. **สะสาง 290 ใบที่ค้าง** ครั้งเดียว: ใบไหนยังใช้ได้ → ใส่วันโพสต์, ใบไหนตกยุค → archive (ตอนนี้ปนกันจนมองไม่ออกว่าค้างจริงหรือแค่ลืมย้าย)

### C. ปิดลูปวัดผล (ต่อยอดของที่มีแล้ว)
11. **ดึง engagement อัตโนมัติ** — มี `meta_sync` + ad tables ที่ดึง Graph API อยู่แล้ว เติมค่า views/reach/eng ต่อชิ้นจากลิงก์โพสต์ที่มีอยู่ 92%
12. **เติม "เคสจริง" ของโปรจาก JERA/events** → ปิดวงจร โปร → คอนเทนต์ → แอด → ลีด → ยอดขาย
13. **แก้สูตร KPI** — ลดน้ำหนัก Discipline ลง เพิ่ม "ชิ้นที่โพสต์จริงตามกำหนด" และ "งานที่ค้างเกิน 30 วัน" (ติดลบ) ให้ตัวเลขสะท้อนผลงานจริง
14. **แก้ท่อ sheet_ingest** ให้เก็บครบทุกคอลัมน์ (F16) ก่อนใช้ hub เป็นหลักฐานย้อนหลัง

### ลำดับที่แนะนำ
A1–A3 (ความปลอดภัย) → A4–A5 (ล้างข้อมูล) → B6–B7 (โครง Trello) → B10 (สะสางค้าง) → C11–C13 (วัดผล)
ข้อ B ทั้งหมดสอดคล้องกับ [CONTENT_MODULE_REDESIGN.md](CONTENT_MODULE_REDESIGN.md) ที่ออกแบบไว้แล้ว — ถ้าจะทำหน้าใหม่ 6 หน้าตามแผนนั้น ควรทำ A + B ก่อน ไม่งั้นหน้าใหม่จะดึงข้อมูลชุดเดิมที่พังอยู่

- ไม่ได้อ่านโค้ด Apps Script ของชีต (ตรวจจากข้อมูลผลลัพธ์อย่างเดียว) — สาเหตุที่อีเมล/KPI ไม่ยิง อาจอยู่ที่ trigger ที่ถูกปิด ไม่ใช่ตัวสูตร
- ไม่ได้ตรวจไฟล์แนบ/thumbnail ในการ์ด Trello รายใบ (965 จาก 1,309 ใบมีไฟล์แนบ แต่ไม่ได้เช็คว่าเป็น thumbnail ตามที่ตองสั่ง 14 ก.ค.)
- ยอดขายที่มาจากคอนเทนต์/โปรแต่ละตัว — ยังผูกไม่ได้เพราะหน้าบ้านยังไม่กรอกยอดปิด (ประเด็นเดิมจาก leadmkt pipeline)
