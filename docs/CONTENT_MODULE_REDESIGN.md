> บันทึก: 27 มิ.ย. 2569 · ที่มา: พี่เซิน (ผู้บริหาร) อธิบาย SOP จริงของทีมคอนเทนต์
> สถานะ: ออกแบบเสร็จ · รอลงมือทำเป็นเฟส (ดู "แผนเฟส" ท้ายเอกสาร)

## 1. รอบการทำงานจริง — Rolling 3-Horizon (รายเดือน)

ในเดือน M เดียว ทีมคอนเทนต์ (น้อง) ทำ **3 อย่างพร้อมกัน** แต่ละชิ้นเดินจาก "วางแผน" วันนี้ ไปโพสต์จริงในอีก ~2 เดือน:

| ขอบฟ้า | ทำอะไรในเดือน M | ช่วงวัน | เดดไลน์ |
|---|---|---|---|
| **M+2** | **วางแผน** คอนเทนต์ล่วงหน้า 2 เดือน | 1–10 | **วันที่ 10** = แผนเสร็จ |
| **M+1** | **ผลิต** คอนเทนต์ (ถ่าย/ตัด/รีวิว) + **ตั้งโพสต์** | 11–14 (เสร็จ 15) | **วันที่ 15** = ผลิตเสร็จ + ตั้งคิวโพสต์ลง M+1 |
| **M** | **เผยแพร่** (โพสต์จริง) + เก็บ engagement | ตลอดเดือน | — |

**สรุป timeline ในหนึ่งเดือน:**
- วันที่ 1–10: วางแผนเดือน **M+2** → ส่งแผน (deadline 10)
- วันที่ 11–14: ผลิตคอนเทนต์เดือน **M+1** → เตรียมเสร็จวันที่ 15
- วันที่ 15: ตั้ง/เตรียมโพสต์ลงเดือน **M+1**
- ตลอดเดือน: คอนเทนต์เดือน **M** (ที่ผลิตรอบก่อน) ทยอยโพสต์ + วัดผล

### "วางแผน M+2" รวมทุกอย่างในที่เดียว (หัวใจของระบบ)
ไม่ใช่แค่ปฏิทินโพสต์ แต่เป็นศูนย์รวมแผนการตลาด:
1. **คอนเทนต์ทุกประเภท** (วิดีโอสั้น/ยาว, รูป) ทุกแผนก
2. **โปรโมชั่น** — ใช้ AI tool ที่มีอยู่ (ดูข้อ 4)
3. **กิจกรรม / มาร์เก็ตติ้งออฟไลน์**
4. **อินฟลูเอนเซอร์** — ติดต่อ → นัดมาถ่ายทำ
5. **จองคิวถ่ายทำ** — ต้องเช็คคิวคุณหมอ / นักกายภาพ ก่อนนัดถ่าย

## 2. โครงหน้าใหม่ — เรียงตาม Stage (ปรับจาก 14 เมนู → 6 หน้า)

เดิม 14 เมนูแยกตามฟีเจอร์ → จัดใหม่ให้ **เดินตามรอบงานจริง** (plan → produce → review → live):

| # | หน้า | Stage | รวมเมนูเดิม |
|---|---|---|---|
| 1 | **วางแผน** (ปฏิทิน M+2) | วันที่ 1–10 | cnplan + **โปรโมชั่น** (promo) + **อินฟลู** (cninflu) + *ใหม่: ออฟไลน์ + จองคิวถ่าย* |
| 2 | **ผลิต** (บอร์ด + สร้าง/อัปโหลด) | วันที่ 11–14 | cnboard + cndraft |
| 3 | **คิวงาน** (รีวิว ตอง→เซิน → ตั้งโพสต์) | วันที่ 15 | cnreview + cnqueue |
| 4 | **เผยแพร่ & ผลงาน** (โพสต์เดือนนี้ + วัดผล) | เดือน M | cnqueue(โพสต์) + cnkpi + cnmonthly + cnhighlight + cnperf |
| 5 | **ประจำวัน** (Brief + Check-in) | ทุกวัน | cnbrief + cncheckin |
| 6 | **ตั้งค่า/Sync** | — | cnsync |

แต่ละหน้าใช้ **tab navigation** สลับมุมมองภายใน (เช่น หน้า "ผลิต" = แท็บ ปฏิทิน·บอร์ด·สร้าง) — reuse ฟังก์ชัน mount เดิม ไม่เขียนใหม่

ระบบควรมี **ตัวนับเดดไลน์** บนหัว: บอกว่าตอนนี้เดือนไหนอยู่ stage ไหน เหลือกี่วันถึงวันที่ 10 / 15

## 3. ฟีเจอร์/ข้อมูลใหม่ที่ต้องเตรียม (จาก mockup ที่อนุมัติ)

1. **`content_type`** — ประเภทงานต่อชิ้น: คลิปสั้น / คลิปยาว / รูปภาพ (โชว์เป็นป้าย + ไอคอน + ความยาวคลิป)
2. **รูปพรีวิว (thumbnail)** ต่อชิ้น — ในการ์ดและหน้ารายละเอียด
3. **กดการ์ด → หน้ารายละเอียด** — รูปใหญ่, แผนก/ประเภท/หัวข้อ, ผู้ดูแล, กำหนดส่ง, แคปชันร่าง, ไทม์ไลน์สถานะ, ปุ่ม action
4. **ตัวนับการใช้ AI รายคน** — `ai_assist_count` บันทึกทุกครั้งที่กด "ให้ AI ร่าง/ช่วยปรับ" ต่อคน/ต่อชิ้น → แสดงสถิติ "ใครใช้ AI ช่วยมากแค่ไหน" (เช่น แยม 64%, แฟร์ 83%)

- เอกสาร: `docs/PROMO_DESIGN_ระบบออกแบบโปรโมชั่น.md`
- **วิธีใช้:** หน้า "วางแผน" ดึง/ลิงก์ตัวนี้มาใส่ในปฏิทิน M+2 — ไม่สร้างเครื่องมือโปรโมชั่นใหม่ (cncampaign ปัจจุบันเป็นแค่ list read-only ของโปรฯ ให้ชี้ไป promo_design แทน)

## 7. Taxonomy ของชิ้นงาน (content piece) — lock แล้ว 27 มิ.ย.69

ชิ้นงาน 1 ชิ้น = ติดแท็ก 4 มิติ (เลือกอย่างละ 1) + เลือกช่องทางที่จะโพส (หลายช่อง):

| มิติ | ค่า | หมายเหตุ |
|---|---|---|
| **แผนก** (dept) | กายภาพ · กระดูกและข้อ · พิลาทิส · Hybrid | Hybrid = collab หลายแผนก |
| **รูปแบบ** (format) | วิดีโอสั้น (<1น.) · วิดีโอยาว (≥1น.) · รูปภาพ · **Reel/Short** · **Carousel/อัลบั้ม** · **Story** | core 3 + เพิ่ม 3 (พี่เซินยืนยัน) |
| **หัวข้อ** (topic) | 11 pillars (Educational/Health, Myth-busting, FAQ, Demo, Reaction, Influencer, Engagement/Trend, Mini-Test, BTS, Prevention, Campaign/Seasonal) | |
| **ลักษณะ** (kind) | คอนเทนต์ปกติ · โปรโมชั่น · อินฟลู · กิจกรรมออฟไลน์ | โปรโมชั่น → ผูก promo_design |

### ช่องทางจริง (ยืนยันโดยพี่เซิน 27 มิ.ย.69) — สำคัญ
- **FB:** ทุกแบรนด์มีเพจ FB ของตัวเอง (5 เพจ) → ชิ้นงานลง FB เพจ**ตามแบรนด์**
- **IG / TikTok / LINE:** มี**บัญชีเดียว = เยียวยา สหคลินิก** และ**โพสทุกชิ้น** (umbrella, รวมทุกแผนก/ทุกแบรนด์)

| แบรนด์เพจ (FB id) | FB | IG | TikTok | LINE |
|---|:--:|:--:|:--:|:--:|
| KneeCare by Yiaoya Clinic (440009909190756) | ✓ (เพจตัวเอง) | — | — | — |
| OrthoCare by Yiaoya (884201461440567) | ✓ | — | — | — |
| Resto Pilates (558498130687803) | ✓ | — | — | — |
| Pakkai by Yiaoya (906687682523310) | ✓ | — | — | — |
| **เยียวยา สหคลินิก** (144036758782939) | ✓ | ✓ (กลาง) | ✓ (กลาง) | ✓ (กลาง) |

**กฎการเลือกช่องอัตโนมัติ (default ต่อชิ้น):**
- เลือกแบรนด์/แผนก → FB = เพจของแบรนด์นั้น (1 เพจ)
- + เยียวยา IG + เยียวยา TikTok + เยียวยา LINE (เติมอัตโนมัติทุกชิ้น เพราะ IG/TikTok/LINE เป็นบัญชีกลางที่โพสทุกอัน)
- ติ๊กออก/เพิ่มได้เอง (เช่น collab โพสหลาย FB เพจ)

> แผนก↔แบรนด์: ส่วนใหญ่ 1:1 (KneeCare/OrthoCare=กระดูก, Resto=พิลาทิส, Pakkai=กายภาพ, เยียวยา=รวม) แต่ KneeCare/OrthoCare ซ้ำแผนก → ให้ "แบรนด์" เป็นช่องเลือกของตัวเอง ไม่ derive จากแผนกตรง ๆ (auto-suggest อิงแผนกเป็นค่าเริ่มต้น แก้ได้)

### implication ต่อ data model
- เพิ่ม field: `format` (6 ค่า), `kind`, `brand` (FB เพจ), `channels[]` = array ของ {target, status, link}
  โดย target ∈ { FB:แบรนด์X, IG:เยียวยา, TikTok:เยียวยา, LINE:เยียวยา }
- field เดิม `fb_link/ig_link/tt_link/line_link` ใช้ต่อได้ (fb_link = เพจแบรนด์, ig/tt/line = เยียวยากลาง)
- per-channel status: เลือกโพส / ตั้งเวลา / โพสต์แล้ว — หน้า "คิวโพสต์" + "Performance" แตกตามช่องได้
- ปฏิทินวางแผน + บอร์ดผลิต กรอง/แสดงตามมิติเหล่านี้ได้
